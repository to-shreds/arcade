# Arcade 2.10.0 agreed scope

Baseline: canonical to-shreds/arcade main dc96bfb0a35499f18dfe115edea03cd599fee0cb.
Add two tiles, Train Trouble and Robot Workshop, preserving all 47 existing entries.
The user approved implementation after reviewing this plan and its trolley revision.

## Train Trouble

An age-eight railway dispatcher with short challenges and visible cause/effect.
Campaign jobs introduce routing, switches, signals/holding, different train speeds,
cargo destinations, rescue/repair/coupling tasks and progressively busier railways.
Pause, slow speed and route previews support learning. Earned cosmetic options and
checked seeded endless schedules provide replay without paid dependencies.

Include multiple short bundled crash movies: extravagant cartoon destruction,
accordion locomotives, flying wheels/cargo and visibly safe soot-covered occupants.
They must play offline, support Skip/Replay, and have a fallback when autoplay is
blocked. Ordinary dispatcher collisions are not graphic human-injury scenes.

Trolley Trouble is a separate mode in the same tile. Present the facts before each
choice, show its consequence, then continue. Related scenarios vary meaningful
facts as separate questions: familiarity, responsibility, certainty, risk, rescue
and infrastructure stakes. Mix serious and lighter settings; darker death/injury
outcomes are stated without depicting bodily harm. No explanation questionnaire,
personality judgment, moral score or single supposedly correct ethical answer.
Risk outcomes must preserve their seed/result through saves and shared handoffs.

## Robot Workshop

An actual circuit-building game, not a gate-identification quiz. Around 30 designed
teaching levels introduce switches/lights, AND/both, OR/either, NOT/opposite,
XOR/exactly one, combined gates, branching wires and multiple machine outputs.
Use visible signals and machine actions, native touch alternatives to dragging,
keyboard controls, undo and progressively revealing counterexample hints.

Accept any circuit that satisfies all relevant input combinations. Generated
endless puzzles must be solvable and reject trivial/broken constructions; difficulty
must reflect required logic, not just visual clutter. Free workshop supports
building and experimenting independently. Optional efficiency goals must not block
ordinary completion. Endless means generated replay, not a guarantee of never
repeating any structure.

## Integration and acceptance

- Match the established Arcade theme, menus, local saves and persistent-shell Home.
- Use the existing shared-activity Internet/Nearby framework and its single-controller
  authority. Keep private local saves, room backups, menu access and bounded payloads.
- Preserve exact progress, generator seeds, wiring/simulation state and meaningful
  choices on reload and control transfer. Avoid independent observer simulations.
- Include new assets in the atomic verified offline package. Retain existing APKs.
- Verify engine invariants, campaign/endless solutions, alternate valid circuits,
  malformed state, actual play, touch/keyboard, four-plus layouts, movies, saves,
  shared handoff/private restoration, denied storage and offline reload.
- Complete and verify both games, update documentation/status, publish from the
  canonical repository and return a downloadable complete web release.
